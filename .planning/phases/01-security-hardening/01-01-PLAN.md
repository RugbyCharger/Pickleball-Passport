  <action>
Replace the entire middleware.ts with a proper clerkMiddleware implementation:

1. Import `clerkMiddleware` and `createRouteMatcher` from `@clerk/nextjs/server`
2. Import `NextResponse` from `next/server`
3. Create route matchers:
   - `isAdminRoute`: matches `/dashboard/admin(.*)`
   - `isDashboardRoute`: matches `/dashboard(.*)`
   - `isPublicRoute`: matches `/`, `/packages(.*)`, `/about(.*)`, `/contact(.*)`, `/sign-in(.*)`, `/sign-up(.*)`, `/api/webhooks(.*)`

4. Implement clerkMiddleware callback:
   - For admin routes:
     - Call `await auth()` to get userId and sessionClaims
     - If no userId, redirect to /sign-in with redirect_url param
     - Check `sessionClaims?.metadata?.role` for 'ADMIN'
     - If not ADMIN, redirect to /dashboard
   - For dashboard routes (non-admin):
     - Call `await auth()` to get userId
     - If no userId, redirect to /sign-in with redirect_url param
   - For public routes and all other requests:
     - Return NextResponse.next()

5. Export config with matcher that excludes static files:
   ```typescript
   export const config = {
     matcher: [
       '/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|webp|png|gif|svg|ttf|woff2?|ico|csv|docx?|xlsx?|zip|webmanifest)).*)',
       '/(api|trpc)(.*)',
     ],
   }
   ```

IMPORTANT: The role check uses sessionClaims which requires Clerk to be configured to include role in session metadata. If this is not configured, the check will fail safely (no role = not admin = redirect).

Reference the pattern from 01-RESEARCH.md Architecture Patterns section.
