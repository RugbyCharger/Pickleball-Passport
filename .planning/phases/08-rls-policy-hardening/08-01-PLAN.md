## Objective

Create a Supabase migration that drops all 24 overly permissive RLS policies ("Dev Access" and "Allow all for development") from the database.

## Context

- App uses Prisma which connects via Supabase service role
- Service role automatically bypasses RLS (Supabase built-in behavior)
- Dropping permissive policies = deny all for anon key (defense-in-depth)
- Tables keep RLS enabled, just no policies that grant anon access

## Tasks

<task id="1">
Create Prisma migration file that drops all permissive RLS policies.

The migration should:
1. Drop "Dev Access" policy from all 20 tables that have it
2. Drop "Allow all for development" policy from Package and Trip tables
3. Be idempotent (use IF EXISTS)

Tables with "Dev Access" policy (20):
- AddOn, Application, Booking, BookingAddOn, Document, GuestProfile
- Itinerary, Message, NewsletterSubscriber, Notification, Package
- PartnerProfile, PartnerReferral, Payment, RefundLog, ReminderHistory
- SupportTicket, Testimonial, Trip, User, WebhookEvent

Tables with "Allow all for development" policy (2):
- Package, Trip
</task>

<task id="2">
Apply the migration via Supabase MCP tool.

Use the mcp__supabase__apply_migration tool to apply the SQL migration
to the production database.
</task>
